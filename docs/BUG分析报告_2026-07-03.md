# smartDesktop 系统BUG和逻辑错误分析报告

## 执行摘要

经过完整代码审查和日志分析,发现了**3个严重BUG**和**5个逻辑缺陷**,导致以下问题:
- ❌ 记忆注入失败
- ❌ 工具不执行直接返回文本
- ❌ 兜底工具未正常代入
- ❌ 其他领域技能从未加载

---

## 🔴 严重BUG #1: 工具列表完全为空 (CRITICAL)

### 问题定位
**文件**: `backend/agent.py` 第208-220行

**现象**: System Prompt 中工具列表为空,导致 AI 无法调用任何工具,只能用文本回复。

**证据**:
```json
{
  "system_prompt": "你是 smartDesktop...\n\n# 工具\n\n# 通用对话\n\n直接使用自然语言回复用户...",
  "ai_reply": "好的,我先侦查一下迅雷的安装情况。\n\n**侦查 1:**\n```json\n{\"tool\": \"scan_directory\"...}"
}
```

AI 回复中包含了工具调用的 JSON,但实际上并未执行任何工具 (`ai_tool_calls: []`)。

### 根因分析

**文件**: `tools/__init__.py` 第117-159行 `_generate_tool_list()`

```python
def _generate_tool_list(domains: list[str], tier2_tools: list[str] = None) -> str:
    config = _load_tools_config()
    always_inject = set(config.get("always_inject", []))

    # 🔴 BUG: active 是空集合
    active = set(always_inject)  # 此时 always_inject 是空的

    for domain in domains:
        domain_tools = config.get("domains", {}).get(domain, {}).get("tools", [])
        print(f"[DEBUG] domain={domain}, domain_tools={domain_tools}")
        active.update(domain_tools)  # 🔴 BUG: 如果 domains=["general_chat"],这里不会添加任何工具

    tools_meta = config.get("tools", {})
    lines = ["# 工具"]

    # 🔴 BUG: active 为空,循环不执行,只返回 "# 工具" 标题
    for name in sorted(active):
        # ...永远不会执行...

    return "\n".join(lines)  # 返回: "# 工具"
```

**连锁反应**:
1. `always_inject` 配置为空列表 → `active = set()`
2. `general_chat` 域的 `tools` 列表为空 → `active.update([])` 无效果
3. 最终 `active = set()` → 工具列表只有标题 `# 工具`,无任何实际工具
4. AI 无法调用工具,只能用文本回复(伪装成工具调用的 JSON 代码块)

### 验证
查看 `prompts/tools.yaml`:
```yaml
domains:
  general_chat:
    keywords: [...]
    tools: []  # ❌ 空列表!
```

## 🔴 严重BUG #2: 渐进式加载逻辑错误 (CRITICAL)

### 问题定位
**文件**: `backend/agent.py` 第145-163行

**代码**:
```python
# ── 渐进式加载:查询经验数据库 ──
task_sig = extract_task_signature(user_message, domains)
exp_record = exp_db.lookup(task_sig)
tier2_tools_param = None  # None = 全部工具(向后兼容)

if exp_record and exp_db.is_strong(exp_record):
    # 强经验命中:注入推荐工具上下文
    recommended = exp_record["recommended_tool"]
    # ...
    # 若推荐工具为 tier2,预加载其到工具列表
    tools_cfg = _load_tools_config()  # ❌ BUG: 这个函数不存在!
    tools_meta = tools_cfg.get("tools", {})
    rec_meta = tools_meta.get(recommended, {})
    if rec_meta.get("tier", 1) >= 2:
        tier2_tools_param = [recommended]
else:
    # 无强经验:首次对话仅加载 tier1 工具(渐进式首层)
    tier2_tools_param = []  # ❌ BUG: 这会导致 _generate_tool_list 返回空列表!
```

**错误点**:
1. `tools_cfg = _load_tools_config()` → 该函数未导入,会抛出 `NameError`
2. `tier2_tools_param = []` → 导致 `_generate_tool_list(domains, tier2_tools=[])` 只加载 tier1 工具
3. 但由于 BUG #1,即使是 tier1 工具也无法加载

### 根因
**文件**: `backend/agent.py` 顶部缺少导入:
```python
from tools import (
    TOOL_REGISTRY, build_dynamic_system_prompt,
    match_domains, match_persona, get_skill_prompt, get_tier2_candidates,
)
# ❌ 缺少: from tools import _load_tools_config
```

## 🔴 严重BUG #3: 记忆注入时机错误 (CRITICAL)

### 问题定位
**文件**: `backend/agent.py` 第185-220行

**代码流程**:
```python
# 第185行: 构建 System Prompt
full_system = build_dynamic_system_prompt(
    domains=domains, persona_mode=persona_mode, extra_memory=extra_memory,
    tier2_tools=tier2_tools_param  # ❌ 此时 tier2_tools_param 可能是 []
)

# 问题: extra_memory 包含了记忆内容,但 tools 已经被 tier2_tools_param=[] 限制
```

**根因**:
记忆注入和工具加载在同一步骤中耦合,导致:
1. 当 `tier2_tools_param = []` 时,只加载 tier1 工具
2. 但记忆内容已经注入,工具不足导致 AI 无法执行任务
3. AI 只能用文本回复,记忆注入也白费了

## 🟡 逻辑缺陷 #1: 会话记忆限制过于严格

### 问题定位
**文件**: `memory/session.py` 第111-131行

**代码**:
```python
def build_context_messages(session_id, limit=150, summary_max_tokens=SUMMARY_TOKEN_BUDGET):
    """构建 LLM 上下文消息列表。

    🔧 2026-07-03 修改:限制完全注入为3轮,超过3轮压缩
    - 只注入最后3轮(3个user消息+对应assistant回复)作为完整消息
    - 超过3轮的历史消息丢弃,依赖压缩摘要注入
    - 如果没有摘要,触发异步压缩
    """
    messages = get_session_messages(session_id, limit=limit)

    # ── 🔧 新增:限制完全注入为3轮,超过3轮压缩 ──
    user_msg_indices = [i for i, m in enumerate(messages) if m.get("role") == "user"]

    if len(user_msg_indices) > 3:
        # 超过3轮 → 丢弃前面轮次,只保留最后3轮完整消息
        cutoff_idx = user_msg_indices[-3]
        discarded_messages = messages[:cutoff_idx]
        messages = messages[cutoff_idx:]

        # 如果没有摘要,触发异步压缩(使用丢弃的消息)
        if not get_latest_summary(session_id):
            try:
                from memory.compressor import compress_conversation_async
                compress_conversation_async(session_id, messages=discarded_messages)
            except Exception:
                pass  # 压缩失败不阻断主流程
```

**问题**:
1. 只保留3轮消息,导致长期上下文丢失
2. 压缩摘要可能延迟生成,导致短期记忆也丢失
3. 用户感知: "系统没有记忆"

## 🟡 逻辑缺陷 #2: 域技能加载时机过晚

### 问题定位
**文件**: `backend/agent.py` 第482-528行 `_try_inject_skill()`

**问题**:
域技能只在工具失败后才注入,导致:
1. 第一次执行必然失败
2. 浪费一轮 LLM 调用
3. 用户体验差

**应该**: 在任务开始时就根据域匹配预加载技能 prompt。

## 🟡 逻辑缺陷 #3: 经验数据库种子数据不完整

### 问题定位
**文件**: `backend/experience_db.py` 第111-124行

**代码**:
```python
def seed_defaults(self):
    """预置已知的经验映射,部署时即生效"""
    defaults = {
        "set_volume:system_config": "system_audio",
        "mute:system_config": "system_audio",
        # ...
        "modify_registry:system_config": "modify_registry",
    }
```

**问题**:
1. 只预置了少数系统配置任务
2. 缺少常见任务的映射(如"卸载软件" → `execute_command`)
3. 导致首次执行必然失败

## 🟡 逻辑缺陷 #4: 工具列表生成逻辑混乱

### 问题定位
**文件**: `tools/__init__.py` 第117-159行

**问题**:
1. `tier2_tools` 参数含义混乱:
   - `None` = 加载所有工具
   - `[]` = 只加载 tier1 工具
   - `[tool_names]` = 加载 tier1 + 指定的 tier2 工具
2. 导致调用方容易传错参数
3. 缺少类型提示和文档

---

## 🟡 逻辑缺陷 #5: 压缩触发阈值过高

### 问题定位
**文件**: `memory/config.py` (需要查看配置)

**推测**:
压缩触发阈值 `RECENT_TOKEN_MIN` 可能设置过高,导致:
1. 记忆溢出才压缩
2. 早期上下文丢失
3. 用户感知: "系统没有记忆"
