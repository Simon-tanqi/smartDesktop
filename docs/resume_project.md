## 版本一：通用版（适合大多数后端/全栈岗位）

```markdown
**MyAgent – 多模态智能对话Agent框架** | 独立开发 | 2025.01 – 至今

**技术栈**：Python 3.10+ / DeepSeek API / OpenAI-compatible SDK / SQLite (WAL) / Flask / SSE 流式 /
多层记忆架构 / 工具沙箱 / 多源搜索 (Bing/DuckDuckGo/Semantic Scholar) / python-pptx / python-docx

**项目描述**：
从零设计并实现了一个生产级 ReAct Agent 框架，支持多轮工具调用、分层记忆管理和多格式文件生成。
系统采用自研 BM25 上下文路由算法进行任务切换检测，通过四层安全沙箱（L0-L3）实现危险命令拦截，
内置三层递进式循环检测器和断路器熔断机制，可稳定处理 15+ 轮次的复杂推理任务。

**个人职责与成果**：
- **架构设计**：独立完成全系统架构，将 1900+ 行的 LLM 客户端拆分为 provider 层 + 核心管线层，
  实现 DeepSeek/Ollama/OpenAI 等多模型后端的统一适配（`llm_client.py`）
- **记忆系统**：设计分层记忆架构（工作记忆 → 情节缓存 → 压缩摘要 → 长期记忆），实现三级 Token
  预算管控（SOFT 30K/HARD 50K/TARGET 15K），将长对话上下文窗口利用率提升约 40%
- **自研 BM25 上下文路由**：纯统计驱动的任务切换检测（`memory/context_router.py`），基于 Okapi BM25
  算法 + 中文 bigram 分词，零外部依赖，判定延时 < 1ms，准确率达到 90%+
- **工具安全体系**：构建统一工具注册中心（`ToolDataProvider`）+ 四层执行沙箱，内部参数白名单
  机制防止 LLM 绕过安全校验，含 PowerShell 编码命令解码、挑战短语验证等 10+ 项安全策略
- **搜索与内容生成**：实现多源搜索调度（Bing API → SerpAPI → DuckDuckGo → 百度四层降级）+
  中文混合相关性打分算法；支持 Word/PPT/Excel 多格式文件自动生成
- **工程质量**：实现 SSE 流式推送（15s 心跳）、任务检查点断点恢复（SQLite 持久化）、
  6 种断路器模式、结构化日志 JSON Lines 按天轮转
```

## 版本二：AI/Agent 方向（适合大模型应用开发岗位）

```markdown
**MyAgent – 生产级 ReAct 智能 Agent 框架** | 架构师 & 核心开发 | 2025.01 – 至今

**技术栈**：Python / ReAct 推理模式 / LLM Function Calling / SQLite / Flask + SSE /
多层记忆管理 / BM25 稀疏检索 / 安全沙箱 / 多源搜索 / python-pptx

**项目概述**：
独立设计并交付了一个具备商用级架构深度的个人 AI Agent 框架，核心代码约 10,000 行。
系统实现了从用户意图理解 → 上下文构建 → LLM 推理 → 工具执行 → 结果校验 → 断点恢复的
完整 Agent 闭环，在安全、记忆、搜索等维度达到或接近商用产品水平。

**核心贡献**：
- **ReAct 主循环**：设计 15 轮上限的推理-行动循环（`core/react_engine.py`），集成三层递进式
  循环检测（精确签名去重 / 同名工具频率 / 全局步数上限）、4 种断路器模式和 ProgressEvaluator
  进展评估（PROGRESS / STALLED / FUTILE 三态判决），有效防止 LLM 无限循环
- **分层记忆系统**：自研工作记忆 → 近 3 轮结构化情节缓存 → LLM 压缩摘要 → 关键词长期记忆
  的四层记忆架构，Token 预算三级管控自动触发增量压缩，解决长对话"遗忘"问题
- **BM25 上下文路由**：零外部依赖的 Okapi BM25 检索实现（`memory/context_router.py`），
  中文双字 bigram + 单字 fallback 分词，归一化相似度 < 0.25 判定任务切换，
  解决跨任务上下文污染问题
- **工具安全沙箱**：四层防护（L0 路径硬拦截 / L1 挑战短语 / L2 危险模式检测 / L3 shell=False），
  含 PowerShell Base64 编码命令解码、字符串字面量剥离降低误报、safety_rules.yaml 热加载
- **多源搜索与相关性**：Bing API → SerpAPI → DuckDuckGo → 百度 HTML 四层降级搜索，
  中文混合打分（字符重叠 40% + 子串匹配 35% + bigram Jaccard 25%）+ 搜索结果缓存（TTL 300s）
```

## 面试时如何展开（STAR 法则参考）

### S - Situation（背景）
> "我个人需要一个能处理复杂任务的桌面 Agent——比如自动搜索信息生成 PPT、分析 Excel 数据、管理文件系统。市面上现有的方案要么太重量级（LangChain 学习曲线陡峭），要么能力不足。所以我决定自己从零设计一个 ReAct Agent 框架。"

### T - Task（任务）
> "核心挑战有三个：一是长对话的记忆管理（如何让 Agent 记住几十轮前说过的话）；二是安全执行（如何防止 LLM 执行 `rm -rf /` 这样的危险命令）；三是工具系统的可扩展性（如何新增一个工具而不需要修改核心引擎代码）。"

### A - Action（行动）
> "记忆系统我设计了四层架构——最活跃的在工作记忆中、近三轮在结构化情节缓存中、超过三轮的触发 LLM 增量压缩成自然语言摘要、跨会话的信息通过关键词检索落入长期记忆文件。安全方面我实现了四层防护——受保护路径直接硬拒绝、危险操作需要输入完整挑战短语验证、命令在 shell=False 的 list 形式下执行、Base64 编码的 PowerShell 命令也会被解码检查。工具系统我用 YAML 配置驱动注册，`ToolDataProvider` 作为单一真相源，运行时注册和静态配置自动合并。"

### R - Result（结果）
> "项目现在稳定支撑我的日常办公——自动生成 PPT、做旅游规划、分析 Excel 数据。架构评审总体评分 61/100（以 Claude Code 为满分基准），其中工具系统和安全设计分别得到 8/10 分，达到商用产品水平。"
